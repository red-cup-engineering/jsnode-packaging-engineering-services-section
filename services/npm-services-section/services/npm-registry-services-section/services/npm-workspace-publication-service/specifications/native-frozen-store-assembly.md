# Strict native cached receiving

Code's existing receiveSourceRegistryConsumers optionally selects nativeStoreAssembly
with explicit owned storeBase and receiptDirectory. It composes PNPM Engineering's
received 0.1.0-dev.192 ./native-store-assembly capability, not a second installer,
SQLite serializer, package resolver, import-mode flag, or copied success assertion.

The original receiver retains whole-consumer preflight, committed frozen graph,
authored release-age policy and CJS readPackage hook, independent archive and
installed-member receiving, prior installation preservation, and same-filesystem
atomic transfer. Missing cache content refuses without online fallback or relock.
The default installation behavior remains the original path.

The strict capability qualifies the original manager, binds configuration before
probes, issues the exact command, excludes native cache writers and checkpoints,
and imports only payload hardlinks. Code owns bounded execution through its existing
source-worker process-group owner and retains quiescence, terminal outcome and
original supplier receipt before admitting the graph. A callback return or payload
link alone never certifies installed artifact contents.

This capability creates metadata, directories, launchers and receipt bytes. Its
allocation requires a separate measured finite plan. It does not lower reserves,
alter the refused whole-graph-growth plan, admit missing procurement, replace
Guix incoming closure admission, or claim promotion, commerce or revenue.

## Uncertain worker custody

US-1. An original source-worker `BUILD_WORKER_CUSTODY_UNCERTAIN` is not a settled
installation refusal. Latch that original error at the supervisor boundary,
before supplier receiving, receipt persistence or progress delivery can fail.
Retain its original process observation and captured stdout/stderr, exact
request and staged-input path. A secondary failure is reported alongside the
original error; it must not replace its code, output or retained scope. The
error and fatal refusal retain an immutable `nativeRequest` snapshot even when
all receipt writes fail. Arbitrary progress-callback rejections, including
null/undefined or accessor-bearing objects, are described without coercing them
or evaluating their properties.

US-2. Preserve that worker's staging tree and the prior consumer installation.
Attempt the existing owner's bounded receipt persistence before further
receiving; expose persistence failures honestly. Do not recursively remove a
possibly live writer's cwd, transfer its partial installation, or continue the
remaining consumer wave. Propagate the original error with the partial
receiving receipt. Original output is retained in a separate
`.native-store-uncertain.json` in the already selected receipt directory; its
UTF-8 text comes from the supervisor's existing 32 MiB combined capture bound
(JSON escaping can enlarge the persisted representation). This is not a new
native start/settlement record or an assertion that persistence succeeded.

US-3. The original per-process receiving queue remains halted after uncertainty.
Already queued and subsequent calls refuse with `BUILD_WORKER_RECEIVING_HELD`
before native provider/preparation probes or installation. The held error
refers to the original uncertain scope; it is not a second worker result.
There is no automatic reset or caller-supplied settled flag. Input preflight, the existing canonical-lock materialization from a declared
carried frozen product, and creation/cleanup of a queued but never-invoked
staging tree may have occurred before the queue refuses. This correction does
not move or redefine that original pre-queue materialization. Ordinary settled failures and known non-invocation retain their
existing safe cleanup/continuation behavior; successful receiving and default
callers retain their existing installation semantics.

US-4. This queue latch is process-local, not cross-process durable coordination.
Restarting or importing another module instance does not establish settlement
or authorize retry. The accountable owner must retain and reconcile the
original scope and evidence across process/environment loss. No kill strategy,
recovery controller or restart permission is introduced by this correction.

US-5. PNPM's existing store lease rolls back/closes during exception unwind.
The npm stop/preserve correction does not make that exclusion outlive an
uncertain native reader, prove the reader settled, or permit another store
writer. That supplier lifetime remains a separate receiving obligation; do
not retain an unbounded leaked database handle as a substitute.

The focused original-receiver unit composition covers uncertainty, an already
queued call (deterministically queued before first execution) and later call,
supplier/unwind/receipt/log/progress failures,
settled nonzero and timeout, never-invoked failure, successful replacement and
the ordinary default path. It uses explicit PNPM/unrelated supplier doubles
and the real source-worker with an already-exited harmless child. It establishes
the npm error-path semantics, not native store exclusion, installed artifact
receiving or full package qualification. Native successful integration remains
covered separately by the existing opt-in test and its exact source/toolchain.
