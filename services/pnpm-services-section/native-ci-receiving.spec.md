# Native public CI receiving

## Requirements

NCI-1. Receive the existing manifest receivingTests from original source and from an actually installed archive, without copying missing tests into the artifact or changing the inherited test assertions. Source, packed artifact, installed test consumer and published/live adoption remain distinct stages.

NCI-2. Native supplier selection is a source-owned test dependency: pnpm11.28.5 in devDependencies, Node24.19.0, and the existing qualified distribution digest. semver7.7.2 remains the sole runtime dependency; yaml2.9.1 remains test-only. The original npm11.9.0 packer is also a dev/test supplier, because the qualified PNPM pack command does not accept lifecycle suppression. Generate the owner lock with the actual pinned native manager, then install that exact graph with --frozen-lockfile and --ignore-scripts. Do not borrow another application's node_modules as portable CI evidence.

NCI-3. The existing six receivingTests are the suite enrollment. The public test entrypoint supplies the installed official manager through the original fixture environment contracts. Its one optional case is the explicitly named real private consumer configuration check: public CI must not copy private Newsroom source. All other skips, cancellations, failed starts, signals, timeouts, nonzero outcomes, truncated output and empty execution refuse receiving. The separate optional native files and required original suppliers are enumerated in ci-native-qualification.json; they are not claimed received by this suite.

NCI-4. The qualification entrypoint is test orchestration, not a release publisher. It invokes the original npm pack and PNPM install commands with scripts disabled, verifies actual archive membership for every receiving test and exported leaf, creates a new test-consumer lock natively, then frozen-installs that lock and executes the same archived tests. It records full bounded process output, archive digest and source/consumer lock identities. Original source/manifest/lock bytes must remain unchanged. No credentials, release-age exemption, registry publication, deployment or production authority is supplied.

## Architecture and failure semantics

The original Continuous Delivery generator selects its shared node-package workflow with exact supplier/source references, explicit Node24.19.0 and PNPM11.28.5, and the named test:ci script. Actual repository visibility must be checked at source receiving and by provider event before hosted allocation. No per-package workflow embeds package-manager logic.

scripts/receive-native-ci.mjs derives the existing receivingTests, validates the installed official supplier, and creates isolated fixture HOME/cache/store/log custody. Only explicitly constructed environment fields reach child processes; inherited credentials and user configuration are not test inputs. The bounded existing CA/proxy transport selectors are preserved unchanged for native registry calls, without disclosing values or substituting a VM-specific trust path; no TLS verification is disabled. The archive consumer contains the archive dependency and its actual declared runtime graph, not PNPM or YAML dev dependencies. External native fixture enrollment remains outside this receiving until its original content-addressed providers are supplied. After native execution begins, failed/incomplete runs retain a partial receipt and logs, never a received state. Earlier source/tool/transport preflight refusals stop before native execution and report an error; they do not promise a partial JSON receipt.

The test entrypoint reuses the existing metadata owner's unchanged receiveEnvironment through an internal named export. It supplies invocation identity policy, not new authority: credential-bearing or malformed relay values refuse before command execution with a generic diagnostic that cannot echo them. CA selectors use the existing bounded, unredirected regular-file admission and retain their byte digests. NODE_USE_ENV_PROXY is separately limited to the literal controls0/1 at this CI boundary; the old metadata profile and its relay classifier are unchanged. Six deterministic contract assays cover absent test files, nonzero/start/signal failures, unexplained/empty/incomplete test output, absent archive members, accidentally bundled tools, credential-bearing relay refusal and missing/redirected CA files.
