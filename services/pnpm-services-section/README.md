## Requirements and responsibility

The accepted bounded policy permits a fresh first-party artifact only when its
exact source revision, packed integrity, declared dependency closure, meaningful
test evidence and independently authorized receiving can all be established.
Namespace membership, version freshness, a successful merge, an opaque evidence
string, a caller's `approved` field and review prose do not establish eligibility.
GitHub `COMMENTED` is not automatically rejection or approval: the existing
source receiver makes the judgment under the applicable integration rule.

PNPM owns eligibility and native policy projection. The original npm publication
owner owns pinned source/artifact production, verification results, lock creation
and frozen installation. The existing GitHub owner owns authenticated source
receiving and durable receiving receipts. This section never publishes, installs,
opens credentials, changes clocks, changes a threshold or writes a consumer lock.
Ordinary dependencies, including unqualified first-party dependencies, remain
subject to the consumer's unchanged age rule.

## Architecture and detailed design

The original publisher retains an immutable verification result from real
bounded command execution over exact source and artifact bytes. Each result
binds source repository/revision/directory, artifact identity and SHA512,
declared closure, command enrollment, full process outcome and retained output
digests. Required suites must run and their required cases must pass; optional
skips require an explicit source-owned enrollment. Timeout, signal, failed
start, truncated output, empty execution and uncovered required cases refuse.
Only safe synthetic fixtures and an explicit environment may feed retained
qualification output; secrets and private client material are not qualification
fixtures.

The existing source receiver independently receives that immutable result and
the exact source through authenticated invocation context. Its original receipt
custody supplies the decision, principal and evidence references. A new decision
may qualify an already published artifact; it must not manufacture a historical
source-receiving receipt for its earlier GitHub merge. Historical artifact source
must remain readable after branch movement, so exact immutable source receiving
must not silently substitute the current branch head.

The PNPM predicate compares those retained identities and evidence. The public
policy function is a deterministic transformation, not an authority boundary:
production callers must resolve receipts through original owner custody, not
deserialize caller assertions and label them trusted. The original publisher
must perform that binding before invoking the predicate. No JSON-only public
entrypoint may turn an arbitrary receipt into an effective age exemption.

Native exclusion selection is exact `name@version`, but PNPM's match does not
bind integrity. Therefore original receiving also verifies every selected native
lock entry's origin/integrity against the qualified artifact closure before
frozen installation, and checks lock, manifest and effective policy afterward.
Conflicting duplicate selections, aliases, a changed lock or a changed policy
refuse. Unqualified transitive entries are not promoted by a qualified parent.
For a changed manifest the original lock writer resolves with lifecycle scripts
disabled, validates the resulting lock, then uses the original frozen receiver.

## Existing native age assay

PNPM owns native dependency selection and effective age policy. This existing
section's assay exercises the supported PNPM CLI independently of the candidate
first-party implementation.

The publication command must not change age policy when choosing an isolated
cache. Its native regression supplies the existing publication command projection,
PNPM 11.28.5, loopback metadata and a child-local controlled clock. It observes
Organizing 0.3.4 immediately before and after 1,440 minutes, under strict project
policy, and checks refusal/lock selection plus unchanged manifest and policy.
Metadata is synthetic; no actual supplier tarball or live consumer is installed.

Run from the Code repository with an explicitly qualified native tool and the
publication owner under review:

```sh
QUALIFIED_PNPM_ENTRY=/qualified/pnpm/bin/pnpm.mjs \
PUBLICATION_COMMAND_MODULE=/publication/src/package-manager.mjs \
node --test --test-concurrency=1 test/pnpm-native-release-age.test.mjs
```

The existing Code `test/**/*.test.mjs` runner discovers the same test. Without
both explicitly supplied providers it skips, rather than selecting ambient tools
or reporting native policy receiving. This assay does not qualify the proposed
first-party classifier or establish FeltOS's complete installed closure.
