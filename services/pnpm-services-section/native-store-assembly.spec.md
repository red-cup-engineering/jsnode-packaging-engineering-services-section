# Native store assembly: requirements and design

Status: source-qualified capability; not an issued provider or received production installation.

NSA-1. Avoid expanding and copying a complete common runtime for each source
repair. The original Code consumer keeps the exact frozen graph, owned policy
and hook, original native manager, independently downloaded archives and final
installed-member comparisons. No cache is an installation or policy receipt.

NSA-2. PNPM Engineering owns the native cached-assembly refinement. Its original
pinned PNPM11.28.5 supports frozenStore but its hardlink importer calls linkOrCopy,
including a file-mode normalization path. Neither a flag nor a link-count guess
proves zero copied payload. A separately admitted original importPackage
extension shall use only native hardlinks and refuse normalization, failed
links, unrelated existing targets, escapes and unsupported symlink maps.
It shall not resolve, fetch, unpack, serialize a cache index, run lifecycles,
rewrite policy or copy payload. It returns the native method and retains
cumulative native import counts; it cannot certify the consumer graph.

NSA-3. The pinned extension is supported but deprecated by PNPM11; qualification
must retain that warning, fixed version/source identity and native behavior.
No compatibility with another manager release is inferred. A later native
replacement must be independently qualified before its provider is selected.

NSA-4. FrozenStore's immutable SQLite reader must not race another writer or
checkpoint. Use SQLite's EXCLUSIVE connection mode before BEGIN EXCLUSIVE,
refusing busy custody immediately and retaining the same file identity across
the callback. An ordinary WAL write transaction or agent heavy lock alone is
insufficient. No journal mode or package row changes belong to the lease.
The source supplier uses original Node24.18.0 for this separately qualified
host profile; existing Node24.19.0 provider profiles remain unchanged.

NSA-5. The prepared service binds the received original provider,
effective configuration and owned local hook BEFORE any native probe.\nThe public ./native-store-assembly service issues opaque single-use sessions,\ncomposes only original exact release policy arguments, and retains the fixed\nnative command. Code owns process bounds and separately receives the graph. An
importer-only global hook cannot alter the local frozen hook checksum; native
multiple-importer refusal is retained. No caller-selected program, hook body,
module, copy fallback or authority assertion belongs to the contract.
The original caller owns finite command execution and resource admission.

NSA-6. Qualify real native PNPM imports, hardlink inode identity, unchanged source
and wanted lock, ordinary local readPackage-hook coexistence, zero package
payload writes and release of writer/checkpoint exclusion after success/failure.
Exercise missing-cache, wrong-mode, different-filesystem, redirected/escaping
paths, occupied target and copied/foreign capability refusals. Retain every
failed or uncertain attempt. Pure controls do not establish a real whole graph,
registry uptake, native release, commerce or revenue.

NSA-7. The original full-growth allocation remains refused. A distinct strict
cached-assembly allocation can charge finite new directories, links, launchers
and evidence only after native qualification. Missing contents require separate
bounded procurement; no online retry occurs. Actual Guix incoming closure and
unchanged physical target reserve remain separate admission gates.

NSA-8. Legacy per-user stores with group-writable directory modes are refused
by prepared frozen assembly. The PNPM owner provides a separate, explicit
receiveStoreOwnerPermissions operation through the same qualified native
manager. It receives both existing owned unredirected directories and their
bounded existing index before mutation, then restricts those two directory
inodes to0700 through held native descriptors. It does not traverse content,
change payload modes, copy data, initialize SQLite or claim a frozen lease.
World writable, foreign, missing and redirected custody refuses before changes.
Partial native changes retain a partial receipt on the failure. Exact native
index identity/size/mtime must remain unchanged; original SQLite exclusive
custody and complete graph receiving still follow as separate operations.


### Native receiving preconditions

Receive the real PNPM fixture with a serial test invocation in the original
heavy-command admission, bounded to 1 GiB memory, zero swap and 180 seconds.
The unit uses UMask 0022 so PNPM preserves native package payload modes.
Every test assembly directory explicitly requests mode 0700; the fixture must
never infer private-directory custody from an ambient umask. Before the
low-level frozen read, the original public `receiveStoreOwnerPermissions`
method receives the seeded native store and the test verifies unchanged index
bytes. The separate legacy 0775 case still proves refusal before explicit
owner receiving, payload hardlink/mode conservation, and later frozen offline
assembly. The test must not normalize package payload modes or relax the
strict importer's normalization refusal to pass. Qualification retains all
failed fixtures; no production cache is changed by source receiving.


### Bounded native verification supplier construction

NVP-1. Original Work599/registry17 owns the observed source-provider damage:
a one-dependency GHS lock construction visited864 existing lock entries with
verification concurrency64 despite admitted networkConcurrency1, and retained
metadata by entry count rather than bytes. This correction preserves every
resolution, integrity, tarball/revision, release-age and trust-policy check.
It neither selects trustLockfile nor changes exclusions, timestamps or outcomes.

NVP-2. The existing PNPM owner constructs a distinct native Code tool product,
never an npm registry replacement or a patched live store. Its only input is
the original PNPM11.28.5 package payload: distributionSHA256
e3738fda08262f74611d7a1ffc11b3e87fa52b466c07eb73211d179ebcb98810,
complete559-member/22643309-byte input inventorySHA256
86d641a60ea0b5e9e317e3bf76888f80ec663ca57c8572b1d29ff093d46fb0b7,
and original manifest/entry identities. Reject changed, redirected, linked,
missing or enlarged input before product creation. Use an explicit existing
owned output parent, exclusive new output and full member/execute-intent
receiving. No source directory or installed supplier is edited. Partial
construction remains retained and cannot become a selected provider.

NVP-3. Apply one fixed, source-owned recipe. Forward the selected native
networkConcurrency to lock verification instead of the unrelated default64.
Bound shared package-metadata retention to8MiB with its existing120-second TTL;
bound all verifier-context maps together to8MiB for that invocation. Account
strings, arrays, objects, maps and sets, including key bytes. Pending work remains
deduplicated and accounted separately; settlement updates retention cost,
rejection removes its exact pending entry, and eviction cannot retain a hidden
strong reference. Oversized settled values are not cached but are still fully
checked. Never substitute cache eviction or absent metadata for acceptance.
These encoded-data bounds are not a claim about native process RSS.

NVP-4. The complete output receives a deterministic recipe/source binding,
new distribution digest and payload inventory. The native provider qualifier
selects that exact new digest for the repaired consumer; it does not accept an
old/new digest fallback. The old digest is permitted only as construction input.
The unchanged upstream package name/version identifies provenance, not equality
with the official npm archive or authority to publish that identity. No registry
publication, installation or operating grant follows from a product receipt.

NVP-5. Receiving executes the actual newly constructed PNPM under the original
Node24.18 store-assembly profile, with an admitted serial256MiB/zero-swap
metadata-only fixture. Its controlled native registry must observe maximum
inflight1, all selected entries checked, bounded settled retention including
oversized metadata and rejected promises, and unchanged required refusals for
young versions, missing integrity and incorrect artifact/revision binding.
Retain actual commands, input/output digests, terminal logs and failures.
The unrelated complete store-installation fixture retains its own1GiB contract.

NVP-6. Only after native supplier receiving and current physical admission,
construct the original GHS lock once with the unchanged policies and exact
authored source. Receive only its intended Code17 graph delta and a real frozen
lock-input check; neither claims an installed graph. GHS0.5 publication and
native publisher adoption remain later actual consumer receiving.
