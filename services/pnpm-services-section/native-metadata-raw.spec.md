# Raw abbreviated metadata — closed batch refinement

Status: source contract; pure and synthetic receiving tests do not establish
native acquisition, downstream resolution, policy eligibility or installation.
Owner: the existing PNPM service section. This refines BATCH-1 through BATCH-12;
the existing batch projector, file receiver and WeakMap session own the behavior.

RAW-1. The original seven-field batch input and its serialized projection remain
unchanged. The only additional accepted input has both
`purpose: 'raw-registry-metadata-acquisition'` and `category: 'abbreviated'`.
Partial/unknown pairs, arbitrary queryPolicy or argv, getters and extra fields
refuse before provider or filesystem work. Names remain one to four distinct
exact names in the complete canonical selected-version inventory. The one-name
API is unchanged and does not acquire this refinement.

RAW-2. `policy` remains the original positive strict canonical consumer policy;
all canonical digests, including the actual policy-file digest, remain unchanged.
The existing positive-policy validations still apply. The initial raw profile
refuses `trustPolicy: 'no-downgrade'`. Its separate `queryPolicy` is derived only
by replacing minimumReleaseAge with zero. Exclusions, strictness and other
accepted policy fields are retained exactly, not invented or interpreted as
ownership/qualification authority. A caller cannot supply queryPolicy.

RAW-3. Generate the same private non-installable manifest, wanted lock, root-only
workspace and registry files. Only generated workspace age differs. Existing
fetchRetries0, fetchTimeout15000 and networkConcurrency1 remain. The original
outdated --compatible vector and exact names are unchanged; no --long, install,
additional flag or callback is introduced. Expected mirrors are source-derived
v12/metadata paths, rather than the full profile's v12/metadata-full paths.
Output adds purpose/category/queryPolicy to the existing batch kind. Its hash
binds these fields, canonical policy, generated bytes and complete original
context. Full and raw projections cannot be substituted for one another.

RAW-4. Both producer and offline reader must emit exactly the requested top-level
name matrix, each with latest AND wanted equal to its exact representative.
Existing duplicate-key parsing, output bounds, statuses0/1, no-error/no-signal
requirements and raw receipt retention remain. The old full profile retains
wanted-only acceptance, including legitimately absent latest. The reader adds
only the existing offline flag. The original session owns all transitions,
source/configuration/transport/CA custody, failure/unknown state and replay rules.

RAW-5. File receiving rederives the complete projection before IO. Every expected
mirror must be a stable bounded unredirected regular file; other category files
cannot substitute. Raw coverage remains diagnostic, not a policy gate. For raw
abbreviated files, `rawCoverage.complete` means all selected manifests have exact
name/version identity; timestamps are not required. Separate
`timestampCoverageComplete` and `modified` {present,validTimestamp,timestamp}
report actual index timestamps and native header modified observations. Modified
does not imply eligibility, and invalid/absent timestamps are reported as null.
Selected integrity matches remain separately reported for every selected version.
Full-category diagnostic shapes and timestamp completion semantics stay unchanged.
Only the representative passed through the command; no all-version native parse,
artifact verification, strict-policy or installation claim follows.

RAW-6. Existing cache absence and custody rules apply to the selected category.
A previously received full mirror may coexist with a fresh abbreviated query;
neither is copied, rewritten, relabeled or deleted. Query policy never changes
canonical consumer files. Two categories remain two independently supervised
producer/reader tickets, each under the existing bounds and one finite composing
allowance. Failure stops dependent work and retains partial native effects.

RAW-7. Required pure/synthetic tests cover old byte compatibility, exact paired
fields, getter/extra-field refusal, unchanged canonical positive policy, generated
age zero, no-downgrade refusal, source-derived paths/hash, missing/invalid time and
modified observations, exact latest/wanted matrix, duplicate/extra/missing output,
mirror/category drift, copied/replayed tickets and old full-profile compatibility.
Later original-supervisor HTTPS native qualification must distinguish full versus
abbreviated consumption, absent time and old/recent/missing modified, with no
consumer policy mutation or archive request. A raw pair is not offline resolver
age-readiness: native may legitimately refuse missing time rather than use the
separate full mirror. No new exception or cache rewrite remedies that refusal.
